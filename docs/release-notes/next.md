# Next release

Notes for the release after 2.1.0. Rename this file to the tag (`v<version>.md`) when the version is chosen: the build takes the release text from `docs/release-notes/<tag>.md`.

## In this release

- **The setup assistant finds a clear Wi-Fi channel.** A new step after the Wi-Fi name and password: the router listens for the networks around it for about ten seconds, shows how many it heard on each channel and how strong they are, and suggests the least crowded channel on each band. You can take another one or leave the channel as it is, and nothing changes before the last step. On 2.4 GHz the choice is between 1, 6 and 11. On 5 GHz it is between whole blocks at the width the radio has; blocks that need radar checks, blocks above channel 165 and blocks the country allows far less power on are not offered, and between channels that are about as good, 44 or 149 is preferred, where Apple devices meet for AirDrop and AirPlay. Only channels the router knows to be allowed in the country you chose are offered, and the choice is checked again when the settings are applied.
- **Updates clean up after themselves on every build, not only on a new kernel.** With the settings on the data partition, the joined spare slot or a USB disk, an update between releases that share a kernel (1.5.4.1, 2.0.0 and 2.1.0 do) used to leave old copies of firmware files in front of the new ones, and the package list kept describing the old firmware: old versions, a theme that is gone, a new package missing. The router now remembers the build its settings last ran with and tidies up on the first boot of any other build. Old copies are moved to `.be7000-replaced/` on the settings volume, nothing is deleted, and your settings, added packages and own feeds stay. Feed addresses of an earlier firmware are taken out of the list. This covers settings on a USB disk too: the disk is tidied on the first boot after the update, just before the router restarts onto it, and kernel modules on it that belong to an older kernel are set aside.
- **First-boot scripts of the new firmware run again after an update**, as on any OpenWrt router, so a default that changed in a release reaches routers that keep their settings outside the firmware slot. They leave your settings alone.
- BE7000: **packages you added come back more reliably after an update.** The router installs them again from the new firmware's feed once it is online. It now waits until its feed list names the feeds of the new firmware, so it cannot fetch builds made for the old one, and it no longer keeps the old name of a library that the firmware brings under a new one (`libubox20260721`, now `libubox20261103`): one such name in apk's list made every `apk add` fail with "no such package" until the router had been online and restarted.
- **A theme you chose stays after an update.** The MiWRT theme only takes over on a new install, or when the chosen theme is no longer installed.
- **The app gets its answers faster.** The router compiled the app service's code again for every request from the phone and for every 30-second pass. It now keeps a compiled copy in memory and makes it again when the code or ucode changes. On the Redmi AC2100 a request took 0.6 s and takes 0.2 s, and the passes use a third of the processor time they did. The BE7000 compiled the code in 0.07 s and gains that much per request.
- **Speed shaping works on a new install.** The example queue of sqm-scripts names a port these routers do not have (`eth1`), so switching shaping on in the app or on the SQM page shaped nothing, and the app showed the wrong limits. The example now names the internet port. Only the untouched example is changed: a queue you set up or switched on stays as it is.
- **Changing the router's address in LuCI works.** After a change of the LAN IPv4 address the page confirms the settings at the new address and opens itself there. LuCI sent the confirmation to the old address, where nothing answers any more, so even a correct change was put back after 90 seconds unless you typed the new address into the browser in time; with the address stored as a list (as on the Redmi AC2100) there was no warning either. The page now names the new address and links to it while it waits.
- **The storage wizard says "done" only when it is.** Moving the settings to a USB disk, to the joined spare slot or back is reported as done after the entries were read back from the settings files. `uci` answers success for an `fstab` that does not exist and for a full volume without writing anything, and a move that went by that answer left the router on its built-in storage after the reboot. A missing `fstab` is made before the disk is formatted, so a failure there costs nothing.
- **Factory reset with the settings on a USB disk no longer depends on the disk's name.** At the boot that carries the reset out, the disk gets up to 15 seconds to appear and is recognised by the UUID of its filesystem; a `/dev/sda` that came back as `/dev/sdb` used to leave the reset waiting forever. A disk that was replaced or formatted since has another UUID and is not cleared.
- **System, Storage shows a reset that has not finished**, says why (the disk is missing, it is another disk, it does not mount, a write failed) and offers a restart or a cancel, with a backup of the present settings first. After a cancel the router stays on the slot's built-in storage with the settings it runs with; the disk is not mounted or written.
- **Tailscale is in the package feed**, with its LuCI page: `apk add tailscale luci-app-tailscale-community`.
- **Restarting SSH over SSH no longer switches SSH off.** The service manager of this OpenWrt base ends every process a service started when the service stops, and an SSH session counts as started by the SSH service. `/etc/init.d/dropbear restart` typed in a session therefore ended the session and the restart itself between its stop and its start, and SSH stayed down until the router was restarted or the service was started from LuCI; `rpcd` restarted from System, Startup went the same way and took LuCI's pages with it. The init script now steps out of the service before it stops it, together with the session it was typed in: the session stays open and the service comes back. BE7000 only; the Redmi AC2100 image has the older service manager, which never did this.
- **The LED watcher runs only when it has work**: while an LED uses the "State (MiWRT)" trigger. An LED you move from that trigger to another one now keeps the new trigger; depending on timing it could be switched off a few seconds later.
- BE7000: **security fixes from OpenWrt for the web server and the libraries under it.** The BE7000 image is built from OpenWrt as it was on 29 September 2026; these parts are now OpenWrt's of early November. The web server (uhttpd): request parsing stays inside the bytes that arrived, one address can no longer hold every script slot, and Basic Auth realms are enforced for URL-prefix handlers (three upstream advisories). libubox: an out-of-bounds read in `blobmsg_json`. rpcd and ubus: session ACLs are enforced for callers that are not root, and runtime files are no longer named after the session id. curl 8.23.0. The certificate tool (px5g): a certificate made for an IPv4 address carried that address in a form browsers refuse, and a certificate with no alternative names was one Chrome does not even offer to accept. The CA bundle no longer trusts "emSign ECC Root CA - G3". The C library: integer overflows in `regcomp` (CVE-2026-107891). The Redmi AC2100 image already has the web server, libubox, curl and CA bundle fixes, through OpenWrt 25.12.6.
- BE7000: **on a new install, 5 GHz is on channel 44 instead of 36**, in the same 80 MHz block, so width, power and range are the same. Apple devices meet on 44 for AirDrop, AirPlay and Continuity and leave their network several times a second to listen there while one of those is active; with the network on 44 they need not leave (what that did on the Redmi AC2100 is described below). A router that is already set up keeps its channel: set 44 under Network, Wireless.
- BE7000: **a fresh install gets its country and the 5 GHz key setting once the radios are up.** The first-boot scripts that set the default country (GB, which radar channels and 160 MHz need) and switch off the daily group key renewal on 5 GHz run before the radios have started on a fresh install, so they could find nothing to set there. The service that brings Wi-Fi up on a fresh install now sets both. A router that kept its settings through an update had them set by those scripts.
- Redmi AC2100: **on a new install, 2.4 GHz chooses its channel itself.** At every start the radio measures channels 1, 6 and 11 and takes the quietest, instead of channel 1 everywhere. A router that is already set up keeps its channels.
- Redmi AC2100: **on a new install, 5 GHz is on channel 44 instead of 36**, in the same 80 MHz block, so width, power and range are the same. While AirDrop, AirPlay or Continuity are active, Apple devices leave their network several times a second to listen on channel 44 and miss what the router sends meanwhile. With the network on 44 a Mac was away less than half as often, the slowest tenth of pings to the router took 4 to 12 ms instead of 40 to 65, and a download to it went from about 235 to 305 Mbit/s; with those services idle the channel made no measurable difference. A router that is already set up keeps its channel: set 44 under Network, Wireless.
- Redmi AC2100: **transmit beamforming on 5 GHz, to switch on.** OpenWrt's driver for this router's 5 GHz chip (MT7615) has none; the stock firmware's has, and that is why download was slower than upload. The image now builds the two modules of that driver with a patch by Lutfil Hadi that adds explicit beamforming (`scripts/ac2100/mt76-patches`). At the project's router, original and patched driver in turn, download to a two-stream laptop went from 257 to 404 Mbit/s (median 332) to 472 to 606 (median 526), and repeated frames from 35 in 100 to 5; upload stayed the same. It is off unless you switch it on, because the patch is young (one author; his router and the project's, one client each):

      echo "mt7615-common txbf=1" > /etc/modules.d/mt7615-txbf
      reboot

  Deleting that file and restarting switches it off again; an update keeps the file (checked with the image installed: off after the install, on after the two commands, still on after installing the image again, off after deleting the file). A device that does not support beamforming should be served as before; there was none to test with. With it off the driver behaves as OpenWrt's own. Everything else in the image still comes from OpenWrt's packages unchanged.
- Redmi AC2100: one thing that was tried against the slow download and is not in the image: not sending the two fastest two-stream rates. It was faster most of the time and far slower some of the time (2 runs of 10 collapsed).
- Redmi AC2100: the traffic counter (nlbwmon) gets the netlink buffer it asks for; the kernel cut it to a third and nlbwmon logged that at every start.
- Redmi AC2100: **the updater can download an update.** Before a download it asked for 120 MB of free memory, on a router that has 128 MB in all, so System, Build update and `miwrt-update` could never fetch an image. The free memory is now compared with the size of the image plus 12 MB to spare (more than 23 MB for this router's image, about 37 MB for the BE7000's). Run on the project's router: the download, and the signature and checksum checks after it.
- Redmi AC2100: **flow offloading you switched off stays off after an update.** The first-boot script that switches software offloading on ran again after every update and could not tell "switched off in LuCI" from "never set". It now acts at the first start only.

## Good to know

- The channel step of the setup assistant: devices on the router's Wi-Fi pause for a second or two while it listens. On the BE7000, when the country you choose is not the one the router runs with yet, only the 5 GHz block it is on is offered: its Wi-Fi firmware has rules of its own, and the router learns them once the country is set (change the channel under Network, Wireless afterwards). On the Redmi AC2100 the other blocks of the chosen country are offered at once. A channel is only applied for the country it was suggested for: change the country afterwards and the step listens again, and if it cannot, the channels stay as they are. On the Redmi AC2100 a new install lets 2.4 GHz choose its channel at every start; the step suggests a fixed one there, and "Automatic" is in its list. The step was run in a browser on a Redmi AC2100 up to the review page, with a change of country, a scan that fails and a second scan; applying a chosen channel through the last step, and the step on a BE7000, are not tested yet.
- The first boot of this release on a router updated from 2.1.0 or older does the clean-up once, for everything that collected so far, when a package was ever added or removed on that router (its settings then hold apk's package list, which is how the router sees that they belong to another firmware). A router where apk was never used is not cleaned at this update, and the first-boot scripts it has run before do not run again; it has little to clean, and from the update after this one it is treated like the others.
- BE7000, updating from 2.1.0: programs from packages you added that use libubox or ubus do not start until the router has installed them again from the new feed, a minute or two after it is online. If the internet connection itself needs such a package (`uqmi` or `umbim` for a mobile modem), give the router another way online for that minute, or go back to the other slot.
- BE7000 with the settings on a USB disk: have the disk plugged in when you update. If it is missing or slow at the first boot of the new firmware, the old copies on it are not cleaned for this update.
- Files you listed in `/etc/sysupgrade.conf` are yours to keep: they are never moved, also when the new firmware ships a newer copy.
- After a change of the router's address the device you configure from needs an address in the new network. In another subnet that means renewing its lease within the 90 seconds: replug the cable, or leave the Wi-Fi network and join it again. Over HTTPS the browser asks about the router's certificate once more, for the new address; the settings are confirmed when the sign-in page opens.
- Tailscale is one large program, about 11 MB to download and more once unpacked. On a router that keeps its settings on the 20 MB data partition, join the spare slot (System, Slots) or move the settings to a USB disk first.
- A reset that waits for the built-in storage cannot be cancelled on the Storage page: it can only be stuck on a half-finished write, and the page says to restart.
- On 2.1.0 and older, do not restart or stop a service from inside it: `/etc/init.d/dropbear restart` over SSH leaves SSH off. If that happened, start it again under System, Startup (dropbear, Start), or restart the router. Changing the SSH settings in LuCI (System, Administration) is safe on every version.
- Other SSH sessions still end when the SSH service stops or restarts; only the session that asks for it is kept.
- BE7000: channel 44, the country and the key setting on a fresh install were checked against made-up settings, not by a fresh install on a router. The two-radio 5 GHz mode still starts its lower radio on 36.
- BE7000: packages for this release are in a feed of their own (`feed/main-d958caf-2`), because libubox and libubus changed and everything is built against the new ones. The router switches to it by itself at the first boot of the new firmware. A router that stays on 2.1.0 keeps its feed as it was on 18 November 2026. One exception: a few programs are published next to the kernel modules, in a directory both versions share because they share the kernel (among them `block-mount`, `blockd`, `uqmi` and `umbim`). They are rebuilt against the new libubox with this release, so on 2.1.0 they can no longer be added or reinstalled; update first.
- Redmi AC2100: automatic channel choice takes about 7 seconds, so the 2.4 GHz network appears that much later after a restart. For a fixed channel, set one under Network, Wireless.
- Redmi AC2100: the texts said packet steering is off. It is on, as OpenWrt sets it for this processor at the first boot, and was on in 2.1.0; a line that meant to switch it off never took effect and is gone. Nothing changes on a router.
- Redmi AC2100, updating from 2.1.0: by hand, once. The updater of 2.1.0 refuses the download ("not enough free memory to download the image"). Take the sysupgrade file from this release and install it under System, Backup / Flash firmware or with `sysupgrade`; `2-update-en.txt` in the archive has the commands. From 2.2.0 on the updater works on this router.
- Redmi AC2100: the image is still in testing. 2.1.0 was installed once from the stock firmware (2.0.23) on one router and ran. Since then that router has had internet on its WAN port (IPv4 and IPv6, closed from the WAN side), checked for updates, installed and removed a package from the feeds, served a Wi-Fi client on each band (5 GHz: 200 to 300 Mbit/s down, 300 to 380 up; 2.4 GHz: about 45 down, 27 up), and been updated, freshly installed and restored from a backup with test builds. The updater's download and checks were run; its install step, applying the setup assistant's settings from a browser (its pages were walked up to the review) and every recovery path are still untested. The texts in the archive now say what was shown and what is not tested yet, tell you to back up the flash first, explain how to reach the stock firmware's old SSH server, and say that the default Wi-Fi password is the serial number without the slash.
