# Next release

Notes for the release after 2.1.0. Rename this file to the tag (`v<version>.md`) when the version is chosen: the build takes the release text from `docs/release-notes/<tag>.md`.

## In this release

- **Updates clean up after themselves on every build, not only on a new kernel.** With the settings on the data partition, the joined spare slot or a USB disk, an update between releases that share a kernel (1.5.4.1, 2.0.0 and 2.1.0 do) used to leave old copies of firmware files in front of the new ones, and the package list kept describing the old firmware: old versions, a theme that is gone, a new package missing. The router now remembers the build its settings last ran with and tidies up on the first boot of any other build. Old copies are moved to `.be7000-replaced/` on the settings volume, nothing is deleted, and your settings, added packages and own feeds stay. Feed addresses of an earlier firmware are taken out of the list. This covers settings on a USB disk too: the disk is tidied on the first boot after the update, just before the router restarts onto it, and kernel modules on it that belong to an older kernel are set aside.
- **First-boot scripts of the new firmware run again after an update**, as on any OpenWrt router, so a default that changed in a release reaches routers that keep their settings outside the firmware slot. They leave your settings alone.
- **A theme you chose stays after an update.** The MiWRT theme only takes over on a new install, or when the chosen theme is no longer installed.
- **The app gets its answers faster.** The router compiled the app service's code again for every request from the phone and for every 30-second pass. It now keeps a compiled copy in memory and makes it again when the code or ucode changes. On the Redmi AC2100 a request took 0.6 s and takes 0.2 s, and the passes use a third of the processor time they did. The BE7000 compiled the code in 0.07 s and gains that much per request.
- **Speed shaping works on a new install.** The example queue of sqm-scripts names a port these routers do not have (`eth1`), so switching shaping on in the app or on the SQM page shaped nothing, and the app showed the wrong limits. The example now names the internet port. Only the untouched example is changed: a queue you set up or switched on stays as it is.
- **Changing the router's address in LuCI works.** After a change of the LAN IPv4 address the page confirms the settings at the new address and opens itself there. LuCI sent the confirmation to the old address, where nothing answers any more, so even a correct change was put back after 90 seconds unless you typed the new address into the browser in time; with the address stored as a list (as on the Redmi AC2100) there was no warning either. The page now names the new address and links to it while it waits.
- **The storage wizard says "done" only when it is.** Moving the settings to a USB disk, to the joined spare slot or back is reported as done after the entries were read back from the settings files. `uci` answers success for an `fstab` that does not exist and for a full volume without writing anything, and a move that went by that answer left the router on its built-in storage after the reboot. A missing `fstab` is made before the disk is formatted, so a failure there costs nothing.
- **Factory reset with the settings on a USB disk no longer depends on the disk's name.** At the boot that carries the reset out, the disk gets up to 15 seconds to appear and is recognised by the UUID of its filesystem; a `/dev/sda` that came back as `/dev/sdb` used to leave the reset waiting forever. A disk that was replaced or formatted since has another UUID and is not cleared.
- **System, Storage shows a reset that has not finished**, says why (the disk is missing, it is another disk, it does not mount, a write failed) and offers a restart or a cancel, with a backup of the present settings first. After a cancel the router stays on the slot's built-in storage with the settings it runs with; the disk is not mounted or written.
- **Tailscale is in the package feed**, with its LuCI page: `apk add tailscale luci-app-tailscale-community`.
- **Restarting SSH over SSH no longer switches SSH off.** The service manager of this OpenWrt base ends every process a service started when the service stops, and an SSH session counts as started by the SSH service. `/etc/init.d/dropbear restart` typed in a session therefore ended the session and the restart itself between its stop and its start, and SSH stayed down until the router was restarted or the service was started from LuCI; `rpcd` restarted from System, Startup went the same way and took LuCI's pages with it. The init script now steps out of the service before it stops it, together with the session it was typed in: the session stays open and the service comes back. BE7000 only; the Redmi AC2100 image has the older service manager, which never did this.
- **The LED watcher runs only when it has work**: while an LED uses the "State (MiWRT)" trigger. An LED you move from that trigger to another one now keeps the new trigger; depending on timing it could be switched off a few seconds later.
- Redmi AC2100: **on a new install, 2.4 GHz chooses its channel itself.** At every start the radio measures channels 1, 6 and 11 and takes the quietest, instead of channel 1 everywhere. 5 GHz stays on channel 36. A router that is already set up keeps its channels.
- Redmi AC2100: the traffic counter (nlbwmon) gets the netlink buffer it asks for; the kernel cut it to a third and nlbwmon logged that at every start.

## Good to know

- The first boot of this release on a router updated from 2.1.0 or older does the clean-up once, for everything that collected so far.
- Files you listed in `/etc/sysupgrade.conf` are yours to keep: they are never moved, also when the new firmware ships a newer copy.
- After a change of the router's address the device you configure from needs an address in the new network. In another subnet that means renewing its lease within the 90 seconds: replug the cable, or leave the Wi-Fi network and join it again. Over HTTPS the browser asks about the router's certificate once more, for the new address; the settings are confirmed when the sign-in page opens.
- Tailscale is one large program, about 11 MB to download and more once unpacked. On a router that keeps its settings on the 20 MB data partition, join the spare slot (System, Slots) or move the settings to a USB disk first.
- A reset that waits for the built-in storage cannot be cancelled on the Storage page: it can only be stuck on a half-finished write, and the page says to restart.
- On 2.1.0 and older, do not restart or stop a service from inside it: `/etc/init.d/dropbear restart` over SSH leaves SSH off. If that happened, start it again under System, Startup (dropbear, Start), or restart the router. Changing the SSH settings in LuCI (System, Administration) is safe on every version.
- Other SSH sessions still end when the SSH service stops or restarts; only the session that asks for it is kept.
- Redmi AC2100: automatic channel choice takes about 7 seconds, so the 2.4 GHz network appears that much later after a restart. For a fixed channel, set one under Network, Wireless.
- Redmi AC2100: the texts said packet steering is off. It is on, as OpenWrt sets it for this processor at the first boot, and was on in 2.1.0; a line that meant to switch it off never took effect and is gone. Nothing changes on a router.
- Redmi AC2100: the image is still in testing. 2.1.0 was installed once from the stock firmware (2.0.23) on one router and ran. Since then that router has had internet on its WAN port (IPv4 and IPv6, closed from the WAN side), checked for updates, installed and removed a package from the feeds, served a Wi-Fi client on each band (5 GHz: 200 to 300 Mbit/s down, 300 to 380 up; 2.4 GHz: about 45 down, 27 up), and been updated, freshly installed and restored from a backup with test builds. An update from one release to the next through the updater, the setup assistant in a browser and every recovery path are still untested. The texts in the archive now say what was shown and what is not tested yet, tell you to back up the flash first, explain how to reach the stock firmware's old SSH server, and say that the default Wi-Fi password is the serial number without the slash.
